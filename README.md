# Карточка ДКП — проверка автомобиля и распознавание паспортов

Статическая страница (GitHub Pages) плюс Yandex Cloud Function `dkp-gigachat-proxy`.
Страница ищет автомобиль по госномеру и распознаёт паспорта сторон договора купли-продажи.

- Страница: <https://koposovds-sudo.github.io/gigachat-ocr-test/>
- Функция: `https://functions.yandexcloud.net/d4e6gg7qd3tlqotvn86c`
- Файлы: `index.html` — фронтенд, `index.js` — исходник Cloud Function (заливается в облако вручную).

## Что делает функция

| Действие | Назначение |
|---|---|
| `lookup_vehicle`, `lookup_vehicle_preview` | Предварительная проверка автомобиля по госномеру |
| `lookup_vehicle_registry` | Регистрационные данные |
| `lookup_vehicle_full` | Карточка автомобиля + регистрационные данные |
| `recognize_passport_page` | OCR одной страницы (параметр `model`: `page`, `passport` и др.) |
| `extract_passport` | Полный разбор паспорта: OCR + шаблонная модель + интеллектуальный разбор |

## Как распознаётся паспорт

1. Основной разворот → Yandex Vision OCR, шаблонная модель `passport` (возвращает структурированные `entities`).
2. Страница регистрации → Vision OCR, модель `page` (обычный текст).
3. Оба текста и найденные `entities` уходят в языковую модель Yandex Foundation Models
   (`POST https://llm.api.cloud.yandex.net/foundationModels/v1/completion`, `jsonSchema`, `temperature: 0`),
   которая ищет конкретные поля и возвращает строгий JSON.
4. Поля собираются по приоритету источников:
   - цифры, даты, ФИО — шаблонная модель Vision → языковая модель → регулярки;
   - «Кем выдан», «Адрес регистрации» — языковая модель → шаблонная модель → регулярки.
5. В ответе есть `source`, `fieldSource` (откуда взято каждое поле) и `llm.error` — они видны на странице
   в блоке «Технические детали».

## Переменные окружения Cloud Function

Задаются в консоли Yandex Cloud: функция `dkp-gigachat-proxy` → **Редактор** → блок **Переменные окружения**.

| Переменная | Обязательна | Значение |
|---|---|---|
| `ALLOWED_ORIGIN` | да | `https://koposovds-sudo.github.io` |
| `TRONK_API_KEY` | да | Ключ сервиса проверки автомобилей |
| `VISION_API_KEY` | да | API-ключ сервисного аккаунта для Vision OCR |
| `YC_FOLDER_ID` | да | Идентификатор каталога Yandex Cloud |
| `LLM_API_KEY` | нет | Отдельный API-ключ для языковой модели. Если не задан, используется `VISION_API_KEY` |
| `LLM_MODEL` | нет | По умолчанию `yandexgpt/latest`. Для скорости можно `yandexgpt-lite/latest` |
| `LLM_ENABLED` | нет | `false` полностью выключает интеллектуальный разбор |

### Права сервисного аккаунта

Ключу, который используется для языковой модели (`LLM_API_KEY`, а если он не задан — `VISION_API_KEY`),
нужна роль **`ai.languageModels.user`** на каталоге. Без неё запрос к Foundation Models вернёт
HTTP 401/403, и в блоке «Технические детали» на странице появится сообщение об ошибке модели.

Как выдать роль:

1. Консоль Yandex Cloud → **Каталог** → вкладка **Права доступа**.
2. Найдите сервисный аккаунт, которому принадлежит ключ (тот же, что для Vision OCR).
3. **Настроить доступ** → **Добавить роль** → `ai.languageModels.user` → сохранить.
4. Для OCR у этого же аккаунта должна остаться роль `ai.vision.user`
   (или `ai.editor` — она включает обе).

Важно про сам ключ: у API-ключа может быть ограниченная область действия. Для языковой модели
нужна область `yc.ai.foundationModels.execute` ([документация Yandex AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-basic)).
Если `VISION_API_KEY` выпущен только под OCR, создайте ключ без ограничений области действия
(или с обеими областями) и положите его в `LLM_API_KEY`.

Если удобнее разделить сервисы, создайте отдельный сервисный аккаунт с ролью
`ai.languageModels.user`, выпустите для него API-ключ и положите его в `LLM_API_KEY`.

## Как обновить функцию

GitHub Pages обновляется автоматически при push, а **код функции в облаке не деплоится из репозитория** —
его нужно заливать вручную:

1. Скопируйте актуальный `index.js` из репозитория.
2. Консоль Yandex Cloud → функция `dkp-gigachat-proxy` → **Редактор**.
3. Вставьте код в файл `index.js`, точка входа — `index.handler`, среда выполнения — `nodejs22`.
4. Проверьте переменные окружения из таблицы выше и создайте версию.

## Проверка после обновления

```bash
# автомобиль
curl -s -X POST https://functions.yandexcloud.net/d4e6gg7qd3tlqotvn86c \
  -H 'Content-Type: application/json' \
  -d '{"action":"lookup_vehicle_full","plate":"А125АА163"}'

# список поддерживаемых действий
curl -s -X POST https://functions.yandexcloud.net/d4e6gg7qd3tlqotvn86c \
  -H 'Content-Type: application/json' \
  -d '{"action":"nope"}'
```

Паспорт проверяйте на самой странице: в ответе поле `source` должно быть `llm_assisted`.
Если стоит `vision_passport_model` или `text_fallback`, откройте «Технические детали» —
там будет причина, чаще всего это отсутствие роли `ai.languageModels.user`.

## Съёмка документов

На странице есть режим камеры с рамкой-гидом в пропорциях бланка паспорта РФ
(разворот 176 × 125 мм → 1,41 : 1, одна страница 88 × 125 мм → 0,704 : 1) и подсказкой по MRZ.
Перед отправкой снимок проверяется по разрешению, резкости и пересветам; загрузка файла
остаётся альтернативой. Изображения сжимаются в браузере (длинная сторона 1600 px, JPEG 0.82),
чтобы не упереться в лимит тела запроса Cloud Functions.

## Безопасность

- В коде страницы нет ключей и секретов, все внешние вызовы идут через функцию.
- Не добавляйте в репозиторий API-ключи и файлы `.env`.
- В запросах к Vision и Foundation Models выставлен заголовок `x-data-logging-enabled: false`.
- Диагностика паспорта (`debug`) возвращается только по явному флагу запроса и отображается
  локально в браузере.
- Если запрос блокируется браузером, проверьте `ALLOWED_ORIGIN` в переменных функции.
